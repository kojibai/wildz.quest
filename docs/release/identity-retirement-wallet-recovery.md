# Identity retirement recovery and wallet loading

The newest supplied account seal passes SDK offline Signature V4 and integrity checks. Its embedded Vault contains 51 creatures. One retirement record lacks the independent mortality admission required by the importer. The previous importer quarantined the entire account, and the Profile upload replaced that diagnosis with a generic identity error. The older supplied legacy seal restores 46 creatures through its signed identity-binding rail; it predates this mortality record.

Browser qualification also exposed a missing `/snarkjs.min.js` runtime required by the SDK verifier, and document retention reused the generic 16 MiB artifact verifier after large-PNG import. The pinned SDK dependency is now shipped and precached; verified documents use a distinct, bounded exact-byte store rather than native source-family custody.

Profile identity recovery now verifies the complete identity/player binding, restores the 50 unaffected creatures, and preserves the affected creature outside playable inventory. The exact input file is retained with the recovery transaction; the complete creature record survives subsequent player saves. It cannot authorize retirement, gameplay, or crew operations. Ordinary card imports still require retirement authority and cannot use account recovery as a bypass. Inventory names the preserved records pending verification. Profile upload now displays the actual restore error.

Wallet overlay cancellation was coupled to background balance reads. An unstable callback also retriggered the overlay effect on each render, repeatedly cancelling and publishing wallet state. The callback is now stable, repeated takeovers are idempotent, and terminal/transfer cancellation leaves the HUD balance read running. Expired read tokens request renewal instead of being treated as explicit revocation. The last successfully loaded current amount remains visible during renewal and transient failures. Retries back off to 30 seconds, pause while hidden/offline, and restart on visibility/connectivity recovery. Identity changes still invalidate state; explicit revocation and mismatched authority still fail closed. No uncertain transfer is automatically replayed.

Neither supplied identity carries a wallet balance; both contain identical-size identity data. No numeric balance decrease or fund movement was established. Current value still requires a successful authenticated read when no known balance is available.

Fixed presentation waits of 180 ms before battle, 300 ms for emergence, 360 ms for capture, and 180 ms for seal reveal were removed. This and removal of the overlay render loop reduce avoidable delay; they do not constitute a zero-latency device benchmark.
