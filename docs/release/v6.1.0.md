# Wildz v6.1.0 — Proof-locked neural continuity

Wildz `v6.1.0` is the stabilization and performance release following `v6.0.0`. It repairs card-selection continuity, standalone-card loading, capture failure handling, roaming pace, claimed-card chat custody, identity-session responsiveness, mobile Send behavior, connected-state noise, creature visual continuity, and the complete Receiz v120 neural voice path.

Release date: 2026-08-17. Receiz release identity: `120.0.0`.

## What changed since v6.0.0

### Creature replies and real neural voice

- Creature replies now stream immediately as `reply_delta` events instead of waiting for the full response.
- The observer consumes official `subjects.twin.streamPerformance` with `responseMode: "performance"`, the exact live context head, and expected proof-subject digest. Voice identity is resolved from the proof-carried creature self model.
- Native v120 audio/performance events travel on the same SSE response as text; Wildz adds no second voice-session call.
- The former Kokoro/ONNX browser model, WASM payloads, model warm-up, generic browser speech, and provider-specific voice session have all been removed.
- The browser uses only native Web Audio decode plus a small deterministic proof transform for rate, pitch, timbre brightness, and gain.
- Actual waveform energy drives mouth motion while the same stream types the text.
- Conversation memory remains exactly as it worked in v6: a genuine observation appends deterministically to the exact live card proof head and survives artifact upload across platforms. Voice never gates or changes that append. There is no local phrase/template or generic voice substitute.
- Repeated proof verification/projection was removed from the Send path: one route-input proof verification and one reused projection now feed the v120 subject/Twin path; the route gains no authority and the client reuses its memoized proof voice lock.
- No new environment variable or runtime dependency is required.
- A mandatory `receiz:architecture-lock` release gate now rejects the displaced provider architecture, runtime MCP/AI imports, non-SDK Twin rails, proof-authority drift, duplicate brain projection, and voice-gated memory.
- The new repository-wide Receiz-first law requires every future capability decision to inventory the exact SDK first, MCP second, AI skills third, and the existing proof path fourth; custom infrastructure is blocked until a reviewed capability-gap record proves no native composition exists.

The full architecture is documented in [Receiz v120 creature voice architecture](../RECEIZ_V120_CREATURE_VOICE.md). The reasoning error that briefly produced unnecessary provider infrastructure is documented candidly in the [v6.1.0 voice reasoning postmortem](v6.1.0-reasoning-postmortem.md).

### Vault cards, current custody, and chat

- A verified card uploaded/claimed into the active Vault is chat-authorized for that current Vault owner through exact membership evidence, even when the carried historical owner field records a previous custodian.
- The claim does not rewrite capture history or subject identity.
- Current ownership reconciliation removes the transferred card from the previous owner's active Vault projection and revokes previous-owner observation/mandate authority.
- The connected proof session is reused after verification; gameplay does not continuously re-run identity verification while the player walks.

### Card selection and standalone routes

- Roaming settlement, conversation append, proof refresh, and other inventory updates preserve the card the player is actually viewing instead of selecting the first card.
- Focus changes still deliberately select the newly focused card, and removal falls back safely.
- Opening `/cards/<id>` now hands off the exact already-verified card through bounded session storage so the standalone page can render immediately while stronger/fresher sources reconcile.

### Roaming experiences

- Active creatures may perform up to 24 bounded acts per day rather than four.
- The first real experience is due within the next five-minute world check, and the first deterministic lived event is a meeting when allowed so the system demonstrates social continuity quickly.
- The UI counts only real roaming actions as experiences, excluding mandate bookkeeping.
- Events remain deterministic, proof-chained, owner-mandated, limited to a 72-hour catch-up window, and zero-write on rejection.

### Capture and server reliability

- Proof-object sealing now has a 12-second upstream timeout and a bounded 30-second server duration instead of leaving the capture request exposed to a long platform termination window.
- Timeout failures return a controlled `504` contract instead of an unclassified Vercel application termination.
- Artifact size, MIME, exact-byte verification, and fail-closed behavior remain intact.

### Mobile and interaction latency

- Send explicitly blurs the active text field, and mobile message/send inputs use a 16 px font floor so iOS does not zoom the player into the form.
- Already-connected identity sessions short-circuit redundant proof/session work.
- Multiplayer presence refreshes were reduced and visibility-aware; local movement/rendering is not gated on identity or network verification.
- Transient network and card-requirement states no longer replace established connected truth with noisy popovers.

### World and creature presentation

- The world gained richer atmosphere, terrain/environment layering, and an upgraded explorer silhouette.
- Live creature actors, Mortal Arena, and Hearttree now use palette and appearance data derived from the exact card artwork so the creature in the world matches the carried card.

## Receiz v120 logic

The release keeps one direction of authority:

1. Verify the enclosing card/Vault and current custody; the proof object remains authority and the server remains only transport/observer.
2. Project exact primary proof objects into the v120 subject brain.
3. Let the Twin reason and perform without granting its output world authority.
4. Stream typed text and neural performance as separate non-authoritative projections.
5. Append the genuine observation through the unchanged deterministic exact-head proof-history path; audio playback neither authorizes nor blocks it.
6. Admit any consequential future action through a separate deterministic command.

`@receiz/sdk@120.0.0` owns application/runtime behavior. `@receiz/mcp-server@120.0.0` validates operator/conformance behavior. `@receiz/ai-skills@120.0.0` supplies engineering doctrine. Neither MCP nor AI skills enter the browser runtime or replace proof verification.

## Hot-path result

The capture and gameplay/render paths contain no speech provider, browser neural model, warm-up, voice fetch, MCP call, or AI-skill runtime. The explicit conversation boundary contains only current-owner verification, one exact proof verification, one v120 proof-subject construction, one official subject-performance stream, bounded typed-event forwarding, native decode, the proof transform, scheduling, and waveform mouth motion.

Text begins on the first native reply delta. Audio begins on the first native v120 `audio_chunk` available to the client. The client records first-text-to-first-scheduled-audio against a 300 ms target. This release does not turn that source instrumentation into an unevidenced universal network-latency claim; authenticated production percentile evidence remains a separate external gate.

## Compatibility and migration

- Existing v5/v6/v119 cards and Vaults remain inputs and are not rewritten in place.
- Historical proof bytes, capture identity, subject identity, and unknown namespaces remain preserved.
- The package version advances to `6.1.0`; the installed PWA shell coordinate advances to `v6.1.0-r1`.
- No voice environment variable needs to be added. Any experimental `RECEIZ_CREATURE_VOICE_API_KEY` value should be removed because Wildz does not read it.
- Offline behavior remains intentionally narrow: the installed shell, previously visited public profiles, and previously visited public cards may remain readable. Sign-in, live world activity, creature intelligence/voice, market, publication, transfer, payment, and settlement require a connection.
- Wildz adds no external database; carried proof objects and owner-scoped local continuity remain the portable source of truth.
