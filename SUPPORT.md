# Wildz support

Use the channel that matches the problem:

- Questions about setup, architecture, or building from Wildz: open a GitHub Discussion if enabled; otherwise open a question issue.
- Reproducible Wildz bugs: open a bug report with the template.
- Feature proposals: open a feature request and describe the product value and authority boundary.
- Receiz SDK or service behavior: first reproduce the issue through the Wildz adapter/doctor and identify whether the fault belongs in Wildz or the upstream Receiz project.
- Security vulnerabilities: follow [SECURITY.md](SECURITY.md); never publish sensitive details in an issue.

Include the Wildz commit/version, Node and pnpm versions, browser/OS, relevant command output with secrets removed, expected behavior, actual behavior, and a minimal reproduction. Do not attach private Vaults, Identity Seals, Receiz Keys, tokens, or production proof objects.

The maintainers cannot guarantee response times or provide private implementation consulting through the issue tracker. Clear, reproducible reports with a proposed test are the fastest path to resolution.
