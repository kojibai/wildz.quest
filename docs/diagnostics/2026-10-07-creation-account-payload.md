# Large-account creation and farm placement

The reported failures were a farm refusing with `creation_world_build_out_of_reach` and several prompts, including a firearm and a ten-room mansion, returning `Creation request too large.`

The proposal request carried the full compiler physical environment, every account admission, and every material lot. The endpoint limits request bodies to 1 MiB. A short valid prompt could therefore be rejected because of unrelated world/account data. Planner validation also walked the unnecessary physical environment on the rendering thread.

Proposals now exclude physical geometry and the duplicate evolution definition, select only chosen crew admissions and budget-relevant owned lot references, and perform JSON encoding, byte counting and HTTP preparation in a cancellable worker. Normal requests retain the authenticated server planner and optional remote enhancement. Evidence over 1 MiB, an HTTP 413, or more than 4,096 eligible lot references produces the same deterministic local proposal in the worker. Authentication refusals do not trigger this fallback. Neither a proposal nor its transport supplies a build receipt or grants resources: the conversation retains its original full context for compilation and live construction admission.

Farm selection previously reused a restored draft's old placement. New farms now sample the current player's position when selected, with a same-space guard; reopening a saved draft and editing an existing object retain their placement. Another failure occurred when a player stood beside a distant pen of a large farm: both admission and final-save checks measured only the farm origin. New commands explicitly select the versioned physical reach rule, allowing a player within 12 metres in 3D of the origin or an actual compiled oriented solid. Empty gaps and render-page bounding boxes do not grant reach. Final admission rechecks the current player. Original unmarked commands retain their original origin rule and exact rule heads; old construction can precede a new evolution in the same replayable history.

Regression coverage includes the pre-fix distant-pen failure, paid farm admission and exact event replay, horizontal/vertical boundaries, rotated thin solids, stale rule-head rejection, mixed legacy/new history, a player moving away before persistence, and the actual farm-selection handler after a restored distant draft. Proposal tests cover oversized exact-draft parity, unchanged mansion room count/material/work charges, HTTP refusal, remote enhancement, stale replies, cancellation, worker failure and resource/collision blockers.

A synthetic 20.4 MB account payload took 72.3 ms to encode on the main thread. Selecting the new compact evidence took 0.87 ms and transferred 1,822 bytes for that scenario. These figures describe that fixture, not the user's hardware. The earlier world-replay change reduced its synthetic maximum heartbeat gap from 842 ms to 4.6 ms. Actual harvest recordings still need the new phase timings to determine the remaining real-account delay; neither benchmark establishes universal zero latency.

A ten-room mansion remains a supported physical composition with its real costs. Firearms require projectile, ammunition and ranged-attack mechanics beyond the current close-range weapon profiles. Requests now explain that missing capability and retain the draft rather than substituting a decorative or close-range object.
