# Market listing publication through the Profile rail

Market's native journal author opened the resource authority session before publishing an advertisement. With the current client configuration, that prerequisite rejected the application ID or proof-authority exchange, so the public-store publication was never reached. Profile already publishes an Identity Seal signed public record without that native-session prerequisite.

List and unreserved withdrawal now compose the same installed SDK `publicStore.signPublish`, `publicStore.publishSigned`, and `publicStore.restoreLatest` primitives as Profile. The local verified Explorer signs the exact selection and price. The relay constrains the complete SDK feed to the Wildz Market namespace and URL family. Receiz verifies the signer. Publication success requires both the accepted registry append and an independently recovered matching public record. The exact signed request is retained before dispatch; uncertain responses recover or retry the same record and idempotency identity. Recovery and withdrawal read the exact URL, independent of the discovery feed's page limit.

These are public advertisements, like Profile gallery declarations. They are not native asset custody, domain replay Originals, reservations, transfer receipts, or payment authority. They never enter the existing native source verifier as proof objects. Native purchase reservations and the Wallet payment/delivery/acceptance paths remain separate. The current native application-registration blocker remains, and a newly published advertisement does not by itself create a native purchasable listing. Full purchasing from these advertisements is not completed by this change.

No Receiz package, server, database, client registration, Wallet credential, or user consent scope changed. The existing native source repository and staged purchase features remain intact. Build still opens from its verified local context.

Validation uses real Receiz SDK signing, public-key signature verification, transport envelopes, actual Market controller actions, and the Next.js relay handler with isolated HTTP responses. Contracts cover List/read/withdraw, account changes, altered feeds and owners, publication-response loss, exact replay after withdrawal, discovery page limits, malformed unrelated entries, relay bounds, safe upstream rejection codes, and zero native-grant requests during publication. Existing staged payment and native acceptance contracts continue to run. This is local integration evidence; no live listing was published and no payment or asset transfer was executed.
