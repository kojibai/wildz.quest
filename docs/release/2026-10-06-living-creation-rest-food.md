# Living creation, rest, food, and harvest recovery

This increment installs the prompt creation controller in the actual game on `main`. A supported prompt can compile, preview, spend exact available material lots, enter the durable world outbox, render, and reopen from the account checkpoint. Selected owned creations can evolve through an exact current-head transition; prior materials, events, and component state remain retained. Construction checks canonical physical obstacles and the current admitted creation projections. Unchanged heads are not rebuilt during restore.

The default local prompt produces a timber home with a clear entrance and usable bed. The local planner has a bounded grammar for homes, furniture, gardens, tools, weapons, shapes, dimensions, materials, and explicit registered graphs. It works without a remote planner or a bearer token for an already verified player. Unsupported mechanics report a reason and retain the draft. Creature techniques come from verified canonical family/work capability, constrained by the current creature condition.

Save produces a source-carrying image through the existing Native device sealer, retains exact verified bytes in the account library, and reopens the retained artifact before download. This action requires an already enrolled device; it does not enroll or introduce another service. Exact source/asset checks precede sealing. JSON digests and domain receipts are not represented as Native artifact authority.

Kai Klok and the Explorer profile show live body readiness, fuel, strain, fatigue, the limiting factor, remaining daily breaths, and exertion. These displays advance analytically without writing a checkpoint on each clock tick. The Kai Klok Satchel action now opens the Satchel. Existing active/camp/bed rates remain unchanged. Ground sleep adds a visible lying-down pose and Kai-based recovery; a valid bed gives deeper recovery. Wake and actual movement settle the prior rest interval before switching activity. Releasing a movement control to open a panel preserves sleep. A terminal encounter does not prevent subsequent camp recovery.

Finite fruit, berries, vegetables, individual native wildlife, and livestock now use owner-bound player checkpoints. Gathering depletes a source; Kai days regrow plants. Eating consumes a portion and restores fuel within fullness limits, without erasing fatigue or strain. Hunting requires an actual equipped axe or a ready verified companion ability. Captured animals need a nearby functional paid room/habitat/garden, including admitted typed creation habitats/gardens. Eggs and milk require a full Kai day and cannot accumulate an unlimited offline backlog. The renderer uses a bounded instanced mesh.

## Harvest regression investigation

The user reported that harvesting worked locally but stalled on live mobile after the prior merge: the creature stayed at a source and no material appeared. Comparing that merge with its first parent shows that the worker/outbox harvest implementation itself was unchanged. The exact physical-phone trigger has not been observed in this environment.

The investigation found unbounded worker and IndexedDB waits, a presentation deadline that only began after awaited admission, and a background synchronization lock whose initial read was outside `try/finally`. Silent worker responses now have a deadline and a fenced replacement. Recovery reads the exact pending or settled durable command before persisting the same identity; an already saved harvest is not written again. IndexedDB open/transaction waits are bounded, late connections close, and stalled transactions abort. The creature's presentation deadline starts at the harvest gesture. A real timber-harvest regression checks one material lot and one source-capacity debit after an interrupted worker. This verifies the repaired failure path, not the user's particular phone or live deployment.

The local production reload check independently exposed `QuotaExceededError` while writing the runtime checkpoint. The durable material outbox survived, but the latest food and sleep snapshot was not retained. Runtime checkpoints now fall back to the existing owner-scoped IndexedDB metadata store when local storage rejects a write; no saved artifacts are deleted to make space. Reopening uses the existing verified inventory/checkpoint boundary and rejects foreign or older state. Explicit restore clears the fallback and fences pending old writes. A silent JSON worker also has a five-second deadline, releasing the queue through its existing serialization fallback. This storage failure was observed locally; it does not establish the exact cause on the user's phone.

## Verification and boundaries

- Full suite: 3,139 tests; 3,138 passed, zero failed, one skipped enrolled-device fixture. Production build passed.
- TypeScript and ESLint: passed; two pre-existing lint warnings remain in BuildGuidanceBrowserFixture and WildsStewardEnvironment.
- Receiz architecture lock passed across 900 runtime files; Receiz v128 integration check and secret scan passed.
- Real production-preview harvest increased timber from 13 to 14, released the working companion, and retained 14 after reload. Under the observed full local-storage quota, a gathered food portion, the plant's reduced supply (1 of 2), and ground sleep survived reload. Eating consumed the portion and restored fuel to 100%; the Explorer panel showed the live sleeping state and energy bar.
- The independent offline qualification script was not run successfully: this process has no `WILDZ_TEST_SEAL_DIRECTORY` for an already enrolled disposable signer. No signer was enrolled to bypass that requirement.
- No dependency or lockfile changes and no additional paid services.

Creation edits remain owner-only and retain at most 64 predecessors. Removal, salvage, component conversion, unsafe occupied geometry replacement, and arbitrary unsupported mechanics are blocked. Registered primitive fidelity is not a claim that arbitrary imaginable content, photorealism, infinite residency, or zero latency is qualified. Food depletion, livestock custody, and hunting wear are owner checkpoints; shared multi-player admission for those consequences is not installed by this increment. Native image download/transfer on the user's enrolled device and physical-phone harvesting still require device qualification.

Production deployment remains the existing GitHub `main` to Vercel flow. A local production preview and a commit on `main` do not by themselves update `wildz.quest`; the deployed commit must be checked separately.
