# Market purchase connection and card funding

Market preserves the working Profile-style signed publication. An explicit sale then qualifies the seller's exact held asset and publishes its separate native listing, with the same listing ID and USD price. The public display fingerprint never becomes custody proof. Failed qualification preserves the public advertisement and exposes a seller retry in Activity. Buyers can review only a separately admitted native listing. Stable saved native attempts recover uncertain replies without creating a replacement listing. Withdrawal closes native availability before withdrawing the public advertisement; an unfinished public withdrawal remains visible after reload.

The buyer reviews the exact USD price, frozen Phi amount, named seller and source. Before approval or payment dispatch, Market reads that buyer's actual Receiz wallet. Insufficient funds open hosted `connect.checkout` for the missing amount, subject to the provider's $0.50 minimum and $100,000 maximum. The same player signs the purpose-scoped wallet funding grant; an MCP agent credential never authorizes the player. Checkout/session responses are admitted using their actual nested SDK wire format. Session ID, buyer, currency, amount and purchase reference must match. Funding the wallet does not prove seller payment or asset receipt. Returning from checkout opens Activity; the buyer explicitly resumes the exact purchase.

Checkout intent and the original session are stored before navigation. Cold unpaid retries reuse the same session. Unknown creation replies read the wallet without creating another card payment. Submitted seller payments reconcile their original nonce and never reopen funding or issue another debit. The existing independently verified Wallet payment, native delivery, recipient acceptance and bilateral closing stages remain authoritative.

## Configuration and baseline

`RECEIZ_CLIENT_ID` and its matching server-only `RECEIZ_CLIENT_SECRET` configure Wallet/Connect. The callback is `https://wildz.quest/api/auth/receiz/callback`. The native source namespace remains `wildz`, already present in baseline commit `307c286c4a7380f3ef3ec038d3909d17d3c58cec`. That baseline's source-SDK transport supplied the OAuth client ID instead; the installed SDK's V124 native application grammar rejects generated `rc_…` IDs. Existing native proof namespaces cannot be renamed to a new OAuth client. This change preserves the current namespace, user identities, existing custody verification and working Build/Profile paths. No Receiz server, database, SDK dependency or secret was modified.
