## Earlier release-blocking audit trail

The following list records the earlier implementation audit. Items 1, 2, and the local-flow portion of 4 are resolved by the current integration checkpoint above. Items 3 and 5 need broader product qualification; live admission, device performance, and deployment evidence remain separate from the source release.

1. Wire admitted v11 site encounters into ordinary discovery and capture. Central legacy gameplay still creates v10 catalog cards; the new region-local scanner locates sites but does not yet admit or capture them. The published v11 odds are not yet the odds of ordinary in-game captures.
2. Carry the v11 birth proof and procedural anatomy through inventory, battle, renderer, card export/import, save, and ownership without weakening existing v10 verification.
3. Migrate remaining fixed-coordinate gameplay authorities and make old central terrain meet new regions without altering existing places. The map entry reaches region-local play from both new and restored sessions, but a smooth geographic transition and all adjacent gameplay authorities still need qualification.
4. Flush offline pending observations into the ordinary encounter and card path, bridge previously restored non-origin travel through verified source evidence, and run a live authenticated Receiz admission probe. The browser encounter path uses the existing authenticated player Connect session; the standalone doctor probes service credentials separately.
   The current travel head accepts client-reported coordinates within a speed bound. That is insufficient as independent proof of physical travel after long idle periods; signed issuance now fails closed with `wilds_v11_player_source_required` until the edge verifies a player object carrying the live site address. A trusted movement source or replayable travel evidence must be added before calling distance-gated issuance fully conformance-grade.
   Removing that head in favor of a caller supplied address was rejected by automatic approval review because it would permit frontier location spoofing. The issuer must stay anchored to verified player source evidence; an outbox entry or session projection cannot replace that source.
   A proposed route carrying the complete sealed player Vault was also rejected by automatic approval review because private Vault contents could reach the Receiz service. That route was not added. A compact source claim or a separately authorized exact-byte Vault boundary is required.
5. Complete embodied creature reactions and revisit/memorial variants for v11 births, transferred cards, and older cards with unknown proven meeting locations.
6. Verify a real capture playthrough and measure frame time, memory, active objects, traversal latency, and first playable time against the 10.1.0 baseline on the same devices. Automated phase tests do not prove zero hitches on all hardware.
7. Complete the release ledger from the first v10.0.0 release, update every app and service-worker version coordinate, and rerun release gates after all gameplay and proof paths are connected.

The source release commit does not imply a tag, push, production deployment, live encounter admission, or device-wide performance guarantee. The user will push the committed source.
