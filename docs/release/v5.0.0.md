# Wildz v5.0.0 — official Kai continuity release

Wildz `v5.0.0` locks gameplay onto one deterministic temporal state machine: the exact non-negative safe-integer Kai Klok `uPulse`, counted monotonically from the fixed Genesis anchor. It is an official semantic-version release rather than an alpha. The reason for the major version is architectural: chapter continuity, shared-world commands, local progression, replay order, and living-creature evidence now agree on one source of temporal truth.

## Why this release exists

Before v5, the product already carried exact Kai evidence in several durable systems, but the live player path could still involve competing observations: browser ISO time, server ISO time, scheduler ticks, polling, and a cached active-chapter projection. Those values usually agreed, but disagreement could make the Wildz Store chapter appear inactive, delay chapter actions, or make a responsive local interaction feel as if it were waiting for remote authority.

The correction is not cosmetic clock styling. Kai Klok is the temporal continuity machine. The current `uPulse` is observed once at the runtime boundary and then advanced monotonically. Every migrated gameplay action carries that exact coordinate. Conventional timestamps remain readable metadata, but changing them while preserving `uPulse` cannot change a gameplay result.

## What was done

### 1. One monotonic runtime clock

The play runtime stores an integer `kaiUPulse`, not an ISO timestamp. A focused clock establishes a baseline from the fixed Genesis arithmetic and advances it using monotonic elapsed time. Later wall-clock observations may move the baseline forward, but they cannot rewind it. React updates only at the next Kai pulse boundary, preserving the existing lightweight render cadence.

### 2. Exact temporal roots on shared-world commands

Every client world command is wrapped in a verified `KaiTemporalRoot` containing exact `uPulse`, coarse pulse, causal sequence, authority label, and coordinate. The network mutation boundary requires the root and fails closed if it is missing or malformed. The server may authenticate, persist, prove, reconcile, or publish the consequence; it does not replace the command's time with server time.

For compatibility, world events still carry ISO fields. Those fields are now deterministic projections of `uPulse`. Two commands with identical gameplay data and the same `uPulse` produce byte-identical chapter events and content-addressed event IDs even when their incoming ISO metadata disagrees.

### 3. Chapter state derived directly from Kai

Story contribution, trainer settlement, and tournament entry derive the active saga from the command's exact `uPulse`. The service reconciles the chapter before executing the action. No scheduler tick is required to open today's chapter, and a stale cached chapter cannot veto it.

If a client genuinely submits a command for a different Kai day, the service rejects it before mutation with a bounded continuity mismatch. The UI refreshes the canonical projection and shows: “The Kai chapter changed. Your story has refreshed—try that action again.” Internal `wilds_*` codes are never presented as player copy.

### 4. Local progression rooted in the same state machine

Local gameplay inputs—including search, capture, encounter transitions, field abilities, battle actions, training, rest, synchronization, fusion, evolution, and ascension—are rooted at dispatch with the current exact `uPulse`. Legacy timestamp-shaped fields remain for artifact and schema compatibility, but their values are derived from the root before the reducer sees them.

Creature growth and exact-card history preserve the originating `uPulse`, so a progression event remains attached to the same deterministic Kai coordinate when it is sealed, exported, restored, or replayed.

### 5. Faster-feeling player path without added weight

The improved responsiveness comes from removing coordination waits and contradictory state sources, not from hiding latency with animation. Chapter readiness no longer depends on a polling response or scheduler arrival. Local inputs resolve immediately against one temporal coordinate, while durable publication can proceed around that gameplay path.

No runtime dependency, render loop, worker, polling loop, state-management framework, image, model, shader, or audio payload was added for the Kai alignment. The core changes are small integer arithmetic, pure derivation, command-envelope verification, and focused state reconciliation.

### 6. NPC Arena and living-card presentation

The NPC Mortal Arena control surface was compacted so its mobile combat controls no longer consume the stage. Movement, primary combat, and contextual survival actions retain thumb-sized targets while the 3D arena and top fighter HUD regain vertical space. The player-versus-player surface remains separate.

Living cards also gain a permanent character-story presentation on the card front, while card-back and growth-panel rules remain separated. These are presentation improvements over the same proof-bound creature identity; they do not introduce a second character record.

### 7. Installed-client release continuity

The PWA service-worker coordinate is bumped to `v5.0.0-r1`. Installed clients therefore request a release-distinct worker and cache instead of retaining a prior alpha shell. State is preserved before applying an update, and activation reloads into one coherent Next.js release.
