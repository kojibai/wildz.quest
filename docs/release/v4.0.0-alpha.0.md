# Wildz v4.0.0-alpha.0 — competitive gameplay alpha

Wildz `v4.0.0-alpha.0` turns the existing world into a deterministic competitive game whose skill, consequences, creatures, and time can be independently replayed and verified. This is an alpha release because the architectural game is complete enough to test end to end, while world-class balance, production authority, performance, accessibility, and representative-player evidence still require live qualification.

## What players get

- A learnable Arena combat model with movement, spacing, facing, stamina, focus, light/heavy commitment, guard, parry, dodge, tags, context interactions, hazards, withdrawals, and exact card abilities.
- A player-facing Adventure Arena and safe Practice projection. The engine also defines Ranked and Mortal policies, but those modes remain deliberately locked until a configured global admission service or signed one-match covenant provider supplies the required authority; the client cannot unlock them locally.
- Deterministic opponents that react only to visible state and bounded history, with no access to future inputs.
- Repeatable mastery drills, deterministic local ghosts, rating divisions, replay checkpoints, and auditable match receipts.
- Creatures whose individual level, XP, bond, mastery, injuries, scars, relationships, achievements, upgrades, form, rank, record, and life state remain attached to that exact creature.
- A real Kai day: `00:00:00` is sunrise at the horizon, midday is the peak, Dream becomes dark and star-lit, and a heading-following lantern keeps creatures readable without turning night into day.

## Integrity model

Kai Klok `uPulse` is the primary temporal coordinate. Causal ancestry resolves first; otherwise only a trusted admitted micro-pulse may choose between divergent branches. ISO timestamps are display and interoperability metadata and never decide authority.

Arena definitions bind the ruleset, stage, roster proof/revision pins, controller profile, and admitted Kai root. Ranked requires a configured signed global admission. Mortal additionally requires a signed covenant bound to one exact match and a durable external `consumeOnce` authority. The client cannot mint either permission.

Terminal Arena state is converted into a canonical transcript and receipt, replayed, and verified before any living card changes. Settlement then updates every affected owned card atomically. A reserve cannot silently lose its injury, history, or mortality because the active leader happened to be the visible card.

Creature history is an immutable content-addressed chain carried inside the Living Card proof append. Standalone card and Vault exports preserve the original Receiz base proof digest while transporting the complete nested history. Causal descendants merge normally; divergent self-asserted authority fails closed; verified death is irreversible.

Carrier integrity is not mortality authority. A retired card or Vault without a configured origin-receipt verifier is preserved byte-for-byte with its memorial projection in retirement quarantine, but it cannot enter gameplay, override a living branch, or enter the market. A configured verifier may admit it only by validating the exact retirement receipt, seal, prior revision, and card/history binding.

## Receiz SDK, MCP, and AI

The app remains pinned to `@receiz/sdk 118.0.0`, `@receiz/mcp-server 118.0.0`, and `@receiz/ai-skills 118.0.0`. The SDK owns artifact verification, custody, proof sessions, and supported remote rails. MCP stays read-only-first and requires explicit confirmation for prepared mutations. AI skills can inspect, simulate, coach, score, and audit, but never sign a covenant, admit a match, publish a branch, or settle a card.

The bundled v118 conformance command currently reports its internal conformance-engine lineage as `112.0.0`; package resolution, compatibility checks, and installed SDK/MCP/AI packages are exactly `118.0.0`. The release record preserves that distinction instead of relabeling the tool output.

There is no external database added by Wildz. Offline support is deliberately bounded: previously visited public profiles and previously visited public cards may be read from the allowlisted cache, while sign-in, the live world, social presence, market operations, and every mutation require a network connection and exact admitted authority. A queued operation is not a global commit.

## Honest alpha boundary

This release does not claim to be the best game in the world merely because its architecture is ambitious. The current weighted implementation score is documented separately. World-class status requires representative novice/intermediate/expert cohorts, device and controller latency, long-session performance and thermals, accessibility qualification, matchup and economy telemetry, tournament operations, production admission services, and authorized strict-live Receiz evidence.

The local repository release is versioned, documented, tested, and committed. Deployment, GitHub publication, production credentials, and live global authority are external operations and must be recorded only when actually performed.
