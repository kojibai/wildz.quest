# Wildz v10.1.0 — Continuity and Control

Release date: 2026-09-26. Baseline: public `v10.0.0` tag (`6f8dccc`).
Application version: `10.1.0`. Installed-PWA release coordinate: `v10.1.0-r1`.
The coordinated Receiz SDK, MCP server and AI skills remain exact public
`127.0.0`; this application release does not invent a new Receiz protocol.

## Player-facing changes

The living world does less work while opening and during play. Optional screens
and panels are deferred until used; deterministic terrain and obstacle results
are reused within bounded caches; materials, geometry and proximity checks
avoid repeated CPU work. World reveal still waits for a completed first draw.
Performance measurements are local samples, not a device-wide latency promise.
The [startup and gameplay measurement record](../performance/startup-latency.md)
includes both improvements and counterexamples. A cold, fully settled screen
below 300 ms is not certified.

Glide and Flight are distinct controls. Glide launches briefly from the ground,
uses aerial energy quickly and stays below powered Flight's ceiling. Eligible
creatures can expose both controls. Collision, protected airspace and safe
landing still govern traversal.

Identity Seal and complete-Vault saves retain the admitted account and prepared
state through recovery. Card level views, save errors, offline large-document
verification and the saved-artifact path received corrections. The wallet now
keeps resource totals and transfer review/editing coherent, and the honey
acquisition path has been exercised. These changes preserve the distinction
between independently verified local proof and live ownership or settlement.

## Integrity and compatibility

The enclosing verified Proof Object remains authority. Local preparation,
browser caches, UI state, a wallet read, a transfer review, and an offline
verification result do not create ownership or settlement authority. Receiz
live application registration and credentials are still required for live wallet
and remote mutation qualification. Historical v10.0.0 artifact coordinates and
the exact v127 SDK/MCP/AI package identity are retained.

The service-worker release coordinate changes to `v10.1.0-r1`, so installed
clients can discover this shell through the existing consent-based update flow.
Hosts that set `NEXT_PUBLIC_WILDZ_SW_RELEASE` must set it to the same value at
build time.

## Release qualification

The release source gate is `pnpm release:check`: architecture lock, full Node
tests, typecheck, official v127 repository check, MCP conformance, lint, secret
scan, production build and Receiz doctor. The browser gate uses the production
server on desktop and mobile to inspect the canvas, core movement, navigation,
errors and changed controls. Record observed results in the release handoff;
do not infer live credentialed behavior from a local fixture.

The exact v10.1.0 source gate passed on 2026-09-26: 2,796 tests passed across
215 suites, zero failed, and one environment-gated offline-sealing integration
test skipped. Architecture lock checked 794 runtime files; SDK/MCP conformance
passed 15 of 15 checks with zero network and database calls. Typecheck, v127
repository check, secret scan (1,665 text files), optimized Next.js production
build (38 static pages) and default doctor passed. ESLint had zero errors and
two existing warnings. The build retained webpack circular-chunk and upstream
`web-worker` dynamic-require warnings. The home route's first-load JavaScript
is 1.39 MB. The doctor reports local identity/artifact capability available
and live API, checkout and webhooks as `needs-env`.

The production build served locally at `http://127.0.0.1:3018/`. Desktop Chrome
rendered a 1,217×726 canvas with 1,825×1,089 drawing buffer; dragging the
movement trackpad changed the world map from X -2, Z -1 to X -3, Z -1 and
reduced energy from 84% to 79%. A 390×844 responsive in-app browser rendered a
390×844 world canvas and visible HUD, world and touch controls. Both views were
visually nonblank. The in-app browser reported no console warnings or errors;
desktop Chrome's warnings originated in an installed wallet extension, with
no application error observed. Opening the local Wallet correctly reported
`receiz_wallet_application_required` and submitted no transfer. No live wallet
settlement, installed-PWA update, physical-device input, browser Save, or
Glide-capable account was exercised in this local preview.

The separate 2026-09-26 performance record reports a fresh local 390×844
Chromium sample at 114 ms to first contentful paint and 1,279 ms to playable
controls. The local starter did not possess Glide; deterministic traversal,
projection and integration tests cover that path. These samples do not certify
the below-300-ms target or all devices.

## Publication boundary

The exact tag, GitHub release and production deployment are separate outcomes.
The operator must review the qualified source, command or permit digest and
current production configuration, then explicitly confirm each publishing or
deployment action immediately before execution. A successful build, local
test, queued proposal or GitHub tag does not prove the production site changed
or a remote Receiz mutation was admitted. Preserve the gate output and browser
evidence with the handoff.
