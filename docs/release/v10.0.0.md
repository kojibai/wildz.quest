# Wildz v10.0.0 — The Living World

Official major public release. Application version: **10.0.0**. PWA version:
`v10.0.0-r1`. Receiz SDK, MCP and AI skills: **127.0.0**.

The previous public GitHub release was v9.0.0, published September 7, 2026.
This release brings together the work since v9.0.0: 89 existing commits touching
659 files before the v10 integration and release preparation. The complete
commit ledger below records that baseline without omitting intermediate fixes.
This document accompanies the release commit; pushing, tagging and publication
remain with the maintainer. Final verification is recorded separately below.

## Explore a living world

Wildz gains more coherent physical geography, detailed foliage, grounded trees,
connected tree silhouettes, physical cave cameras and lighting, and corrected
water behavior around mountain terrain. Cave exits, return detours, landmarks,
movement, collisions and exploration guidance received repeated refinements.
Weather now participates in the built world through persistent storm wear and
material-backed repairs. Discoveries have stories and portable memories; mastery
and expedition progress are earned through gameplay outcomes.

The world atlas has a more complete mobile experience: immediate updates,
retained terrain, a restored horizon title, clearer labeling, free map navigation,
and coordinated pan, pinch and twist controls across atlas refreshes. Discovered
world maps can be exported as game-bearing images and imported again.

## Companions with persistent journeys

Crews can explore independently, travel, harvest and return. Their causal
execution and journeys persist through reloads, with durable reservations and
explicit handling of indeterminate outcomes. Movement controls, pathing,
physical grounding, gait, fresh following and party recovery were improved.
Harvesting companions pause at sources and walk back rather than teleporting.
Restored Vaults recover crew state and world continuity. Roaming battles,
capture, native claim authorization and crew recovery are connected, with
additional protection around source harvesting and cross-browser ordering.

## Build, inhabit and maintain

Continuous construction is now backed by material and work rules, connected
geometry, placement checks, explicit unlocks, functional stages, and community
procedures tied to consent. Building refinements cover underground work,
connected structures, snapped regions and collision coverage. Functional beds,
home activities, construction rewards, persistent wear and repairs make built
places useful beyond placement. Building guidance and progressive explanations
make the available world actions easier to understand.

## Portable identity, cards and Vaults

Identity restoration was isolated across accounts, with repairs to identity
publication, restored collections, crew recovery and complete public Vault
profiles. Captured and uploaded cards can be saved again; publication, claim
checks, public-source recovery and automatic download after verified upload were
refined. The Card Vault preserves retired creatures as readable memorials.

Vault exports reuse verified sections and deltas, prepare identity signing off
gameplay frames, preserve exact sealed source history and retain unrelated
namespaces. Complete game payloads travel with saved images. Card-back downloads
use the same verified export path as the inventory.

For v10, canonical sealing moves from the temporary copied v126 runtime to the
public v127 offline API. Device custody remains local, proving runs in a worker,
and resources come from the SDK package. One-time enrollment precedes offline
sealing. Canonical verification and exact payload checks occur before download.
Cards, Vaults, Identity Seals and maps have real offline round-trip tests. The
[verification record](../game-image-export-verification.md) states the distinction
between a signed backup envelope and native ownership/transfer authority.

## Public profiles and discovery

Public profiles now synchronize more complete Vault data with smaller signed
publication payloads. Background preparation, retry recovery, restored-account
sync and public-card source handling received repeated fixes. Public discovery
metadata, static guides, world-law explanations, social presentation and mobile
HUD controls make the game easier to find and understand. Creature capabilities
are distinct; passive abilities use compact icons instead of crowding controls.

## PHI and the sovereign wallet

Authorized wallets refresh without asking the player to reconnect unnecessarily.
Known balances remain visible during independent reads. Nested Receiz balance
responses are handled without manufacturing a zero. Wallet layout improvements
keep amounts readable and bring game assets and recent ledger activity into the
overview. Fractional amount parsing, recipient clearing/reselection, transfer
preparation feedback and recovery received integration fixes.

These implementation changes are not evidence of a completed live settlement.
Transfers still require exact native authority, recipient and head admission;
local tests and a sealed backup do not confer settlement authority.

## Performance across the game

Startup, capture, movement, building and profiles have extensive performance
work: fewer repeated verification and persistence operations, worker-based
signing and Vault preparation, compact worker messages, indexed nearby buildings,
spatial movement/support indexing, retained geometry and terrain, stationary
collision reuse, bounded aerial scans, coalesced background refreshes, and
reduced scene updates. Known admitted state paints before optional discovery.
These are implemented optimizations, not a claim of zero computation time or
identical frame rates on every device.

## Coordinated Receiz v127 integration

All three packages are pinned together with published lockfile integrity. The
application contract and generated framework metadata use the current release,
60-operation matrix, registry digest and compatible SDK range. Historical V124
and V125 API identifiers and durable saved schemas remain unchanged.

The official offline sealer and MCP tools preserve canonical verification
boundaries. Historical HTTP methods disabled by v127 are not silently re-enabled
against an unsupported host. SDK/MCP/compiler/AI outputs remain below sealed
proof authority. The release retains native transfer checks, exact source
custody, append-only history and independent identity verification.

## Release qualification

The final `pnpm release:check` passed. Repository qualification: 2,739 tests passed, zero failed; one private-device
integration test was explicitly skipped in the ordinary run and passed in a
separate enrolled-device run. Cards, Vaults, Identity Seals and maps passed real
canonical verification, exact payload reconstruction and tamper rejection with
networking blocked. Independent official v127 MCP sealing and verification also
passed with zero network calls. Typecheck, architecture lock, integration checker,
SDK conformance, production build and secret scan passed. Lint has zero errors
and two existing warnings. The build reports upstream bundling warnings.

The local production preview opened the existing BJ Klock identity with 46
creatures. Its wallet authorization could not complete because the local server
lacks `RECEIZ_CLIENT_ID`; the UI reports `receiz_wallet_application_required`.
The local doctor likewise reports missing live configuration. Production
credentials, real send/receive settlement, browser Save through the new worker,
and Camera Roll transformations were not qualified in this run. Do not treat
this repository evidence as proof those unobserved paths have passed. Historical
HTTP portability/release/proof-query methods retired by v127 are excluded from
current live-route qualification and explicitly reported as unavailable by
default. Full details are in the [v127 integration record](receiz-v127-integration.md).

## Maintainer publication

The release commit is prepared locally. Push the reviewed commit, create/push
`v10.0.0` when ready, and use these notes for the GitHub release. If the deployed
environment overrides `NEXT_PUBLIC_WILDZ_SW_RELEASE`, set it to `v10.0.0-r1`.
Use the registered Receiz application configuration for live wallet qualification;
never invent a client ID or substitute a local receipt for completed settlement.
